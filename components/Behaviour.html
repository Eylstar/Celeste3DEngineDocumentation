Behaviour

Class Abstract Component

Behaviour is the base class for all of your custom game logic. It's abstract, so it cannot be used directly, you need to write your own class inheriting from it and override the life cycle methods you need. This is where the actual behaviour of your GameObject lives, movement, interactions, gameplay rules, anything that needs to run over time.

A GameObject can hold any number of Behaviour at once, each one running independently. They are added like any other Component, with AddComponent(), and can be created without any constructor arguments of your own choosing, since Behaviour itself declares none.

Writing and attaching a custom Behaviour 
//A simple Behaviour that spins its GameObject every frame
public class RotatingProp : Behaviour
{
    public float rotationSpeed = 45f;

    public override void Update(float deltaTime)
    {
        transform.Rotate(new Vector3(0f, rotationSpeed * deltaTime, 0f));
    }
}

//Attaching it to a GameObject
GameObject prop = new GameObject("Prop");
prop.AddComponent(new RotatingProp());

Life Cycle


A Behaviour follows the same 5 steps as its owning object, Added, Start, Update, Render and Removed, called at the same time as the matching GameObject step. None of these need to be overridden, only override the ones your logic actually needs.

Added is called once, at the moment the Behaviour's object is added to the Scene with Scene3D.AddGameObject. Scene references may still be unavailable at this point, so use them with caution.

Start is called once, right before this Behaviour's very first Update. It always runs on the same frame as that first Update, whether the Behaviour existed on the GameObject from the start or was added later at runtime.

Update runs every frame after Start has run, at the same rate as the rest of the Scene.

Render runs every frame, after every GameObject's Update step has completed for that frame.

Removed is called once, when the GameObject holding this Behaviour is destroyed.

Setting enabled to false stops both Start, Update and Render from being called for this Behaviour. Re-enabling it later will trigger Start on the next Update if it had not run yet.
Added() is only called for Behaviours already attached to a GameObject at the moment that object is added to the Scene. If you use AddComponent() to attach a new Behaviour to a GameObject that is already in the Scene, Added() will not be called for it, only Start, Update and Render will run normally.
Removed() is only called when the entire GameObject is destroyed with GameObject.Destroy(). Removing a single Behaviour from a GameObject that stays alive, with RemoveComponent(), RemoveFirstFoundComponent() or RemoveAllComponents(), does not call Removed() on it.

Shortcuts

To avoid writing gameObject.transform or gameObject.scene everywhere, a Behaviour gives direct access to its owning object's Transform and Scene3D through the transform and scene properties.

Properties

Property Type Description
enabled bool Whether this Behaviour is enabled and should have its Update and Render methods called, default true
gameObject GameObject The GameObject this Behaviour is attached to
transform Transform The Transform of the GameObject this Behaviour is attached to
scene Scene3D The Scene this Behaviour's GameObject is in

Methods

Method Return type Description
Added() virtual void Called when the GameObject is added to the Scene, the Scene and its 3D models may still not be loaded by the Engine at this point
Start() virtual void Called once before the first Update of the Behaviour
Update(float deltaTime) virtual void Called every frame at the same time as Celeste.Entity.Update
Render() virtual void Called every frame at the same time as Celeste.Entity.Render
Removed() virtual void Called when the GameObject is removed from the Scene
