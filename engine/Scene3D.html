Scene3D

Class

The Scene3D class represents your classical 3D Engine Game Scene. Multiple instances of a Scene3D can be created and loaded at the same time from your mod, but only one can be loaded and used by the EngineEntity.

Each Scene3D contains its own elements and settings and these are only applied for this scene. The Scene3D is made of a list of GameObject, one Renderer3D and Camera3D that handles the 3D rendering, one togglable Skybox, one default AudioListener, an internal CollisionSystem, and its own LightingSettings.

In each scene, you can Add or Remove GameObject with custom code logic, place decoration elements, some Light or use it as a background for your Celeste Gameplay.

Setting the Scene and Adding Objects

Here is a very basic exemple of a Scene3D creation and loading, with the setup of the main Camera3D, one GameObject added and an update of the LightingSettings.

Scene basic setup 
Scene3D scene = new Scene3D();

void SetupScene()
{
    //Exemple Camera3D created, placed, and set as Rendering Camera for the scene
    Camera3D cam = new Camera3D();
    cam.transform.SetPosition(new Vector3(0f, 10f, 5f));
    scene.SetMainCamera(cam);

    //Instantiation of a GameObject for the player, with a 3D model
    GameObject player = new GameObject("Player");
    player.AddComponent(new MeshRenderer("playerModel"));
    scene.AddGameObject(player);

    //Gets the actual settings of the scene and update them
    LightingSettings settings = scene.GetLightingSettings();
    settings.DirectionalLightCastsShadows = false;
    settings.fogColor = new Vector3(0.5f);
    scene.SetLightingSettings(settings);

    //Pass the scene to the EngineEntity to load it. This can be done before or after the previous steps.
    EngineEntity.LoadScene(scene);
}

Finding Objects

Just like in Unity and other Engines, there is some built-in functions for searching and getting a GameObject reference.
Each GameObject possess a name and a tag. Both are by default set as an empty string, but you can change them with GameObject.SetName() and GameObject.SetTag(), or, for the name, specify it in the constructor when you create the object.

You can find and filter objects using these names and tags. Also, if you want to search specifically for Objects with a known Behaviour attached to it, you can filter the search by Type. (Behaviour are components like AnimationPlayer or any of you classes that inherits Behaviour, see more in the Behaviour page).

GameObject Finding 
Scene3D scene;

// Find the first object named "Player"
GameObject player = scene.FindFirstByName("Player");

// Find every object with the tag "Platform"
List<GameObject> platforms = scene.FindAllByTag("Platform");

// Find every object with that has the "EnemyMovement" script attached to
List<GameObject> movingEnemies = scene.FindAllByType<EnemyMovement>();
Finding functions can be heavy, especially if called from Update() and in scenes with a lot of objects. Prefer storing objects references when creating them as much as possible.

Scene Core logic loops

Load

When LoadScene is called on the EngineEntity, the scene initialization starts.

During this, the Scene3D starts by creating a default Camera3D and sets it to be the Rendering one if none was created and set before. You can create yourself your own Camera3D and set it in the scene with SetMainCamera() before or after the scene loading.
The Scene3D also places and set its Skybox with the default sky Texture and initialize its CollisionSystem and Renderer3D.

Skybox.Destroy() is disabled by default. If you don't want to use a Skybox, use Scene3D.EnableSkybox(false) directly in your scene.

Then, the Scene3D will call the OnSceneLoad event, that you can use to invoke code at this precise moment. And finally, Start() will be called on every GameObject that was added before scene load, on the following Update tick.

Note that the Behaviour functions Added() will be called at the exact moment the object is added, even if it's before the scene load. Start() will only be called after the Scene loading and OnSceneLoad event call, ensuring most of the Scene3D core references are initialized and not null. More information in the GameObject and Behaviour pages.

Update

The scene's Update() function is called by the EngineEntity at the exact same rate than the core Monocle/Celeste update tick rate. (since EngineEntity is a Celeste Entity).

At the start of every Update() loop, Start() will be called on every GameObject that was added during the previous frame. Then Update() is called on every GameObject present in the scene, and the AudioListener position is updated.
The Renderer3D will process every Model3D information, and store the result in the appropriate RenderTarget2D for later rendering.

And to finish the Update cycle, the scene will resolve the collisions for every active Collider3D and CollisionDetector, and then clean up and remove every GameObject on which Destroy() was called.

Render

After the Update() loop finishes, a shorter one starts. Render() is called on every custom Behaviour in the scene.
And then, if the debug option is enabled, the loaded Collider3D and RayCast will be drawn into the screen.

This loop is named Render() to follow Monocle/Celeste namings, even if here no real rendering is done. This loop is called exactly when the Celeste entities Render() code is called. It's the same as Update, called at the Celeste tick rate from EngineEntity.
If you need to visually debug things or draw a sprite at the moment Render() would be called in a celeste entity, it can be useful, like for the collider and raycast debug draws, since it will always be drawn over the 3D World (in Celeste Entity.Render is called after Level.Render)

Constructors

Declaration Description
Scene3D() Creates a new 3D Scene

Properties

Property Type Description
debugShowColliders bool Decides if Colliders and Collision Detectors are shown (Wireframes)
debugShowOnlyCollidersInRange bool If debugShowColliders is true, decides if the colliders shown are the ones loaded by a detector or all the colliders
debugShowRayCasts bool Decides if the RayCasts are shown in the scene (Lines and hitPoints)

Methods

Method Return type Description
GetRenderingCamera Camera3D Returns the rendering camera of this scene
GetRenderer Renderer3D Returns the Renderer3D of this scene
GetLightingSettings LightingSettings Returns the LightingSettings used in the scene
GetSkybox Skybox Returns the Skybox object used in the scene
GetGameObjectsList IReadOnlyCollection<GameObject> Returns a readOnly list of all GameObjects in the scene
AddGameObject void Adds a GameObject to the scene
AddGameObjects void Adds multiple GameObjects to the scene
AddHUDObject void Adds a static HUD orthographic GameObject
SetMainCamera void Sets the main rendering Camera for the scene
SetLightingSettings void Sets the lighting settings for the scene
SetPause void Pauses or unpauses the scene update and rendering
EnableSkybox void Enables or disables the skybox rendering
ChangeSkyBox void Change the Skybox Texture
ChangeAudioListenerObject void Changes the GameObject that acts as the AudioListener for the scene
ResetAudioListenerToCamera void Resets the AudioListener to follow the main rendering camera
FindFirstByName GameObject Finds the first GameObject in the scene with given name
FindAllByName List<GameObject> Finds all GameObjects in the scene with given name
FindFirstByTag GameObject Finds the first GameObject in the scene with given tag
FindAllByTag List<GameObject> Finds all GameObjects in the scene with given tag
FindFirstByType GameObject Finds the first GameObject in the scene that has a Behaviour of given Type
FindAllByType List<GameObject> Finds all GameObjects in the scene with a Behaviour of given Type

Events

Declaration Parameters Passed Description
