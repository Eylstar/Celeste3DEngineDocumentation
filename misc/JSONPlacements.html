JSONPlacements

Class
The JSONPlacements class is expected to work only with the Celeste3DEngine Blender Plugin exports. See the Blender Add-On page for how to use it.

JSONPlacements reads a JSON file describing a list of transforms, position, rotation and scale, each tied to a model name, and turns it into something you can loop over to build your Scene. It's meant for placing a large number of instances of the same handful of models, trees, rocks, grass, anything you'd rather place visually once than type out by hand in code.

The JSON Format

A placements file is a flat array of objects. Each one has a model name, and position, rotation and scale as plain number arrays. rotation is a Quaternion, [x, y, z, w], not Euler angles.

A minimal placements.json 
[
  {
    "model": "pineTree",
    "position": [12.3, 0.0, -8.1],
    "rotation": [0.0, 0.34, 0.0, 0.94],
    "scale": [1.1, 1.1, 1.1]
  },
  {
    "model": "rock",
    "position": [15.7, 0.2, -3.4],
    "rotation": [0.0, 0.0, 0.0, 1.0],
    "scale": [0.9, 0.9, 0.9]
  }
]
The model string is only ever a name, it's up to your code to decide what it points to, or if it will even be used.

Loading and Using Placements

GetPlacements takes a virtual content path, the same kind you'd use with any other Engine asset, and returns a list of tuples pairing each model name with a ready to use Transform. Nothing gets added to your Scene automatically, looping over the results and building your own GameObjects is left to you.

Instancing a forest from a placements file 
//Load the Forest.json file, located in a Placements subfolder inside your already set Models folder
string path = EnginePaths.CustomModelsPath + "/Placements/Forest.json";
var placements = JSONPlacements.GetPlacements(path);

if (placements == null) return; //Already logged an error if the file wasn't found

foreach (var (modelName, trans) in placements)
{
    //Constructing the GameObject directly with the Transform constructor
    GameObject instance = new GameObject(trans, modelName);

    instance.AddComponent(new MeshRenderer("BaseTree")); //Each model is the same tree here
    myScene.AddGameObject(instance);
}
Every instance shares the same model, when loading its mesh is cached so placing hundreds of the same tree costs one mesh load, not hundreds.


The example above is for cases where all the models used are the same. You can also use the modelName directly to load the corresponding models all at once without having to have as many placements exports as different models. You just have to be sure the name of the Blender Object (the one who's exported in the JSON) is exactly the same as your model name.

Also note that the exported name in the JSON is everything before the first "." in the blender object name, so "Cube.001" will automatically be exported as "Cube" in the JSON. (see more in the Add-On page)

Using the model name as a lookup key instead 
foreach (var (modelName, trans) in placements)
{
    GameObject instance = new GameObject(trans, modelName);

    //Automatically finds the model asset, if one with the exact same name exists
    instance.AddComponent(new MeshRenderer("Trees/" + modelName));
    myScene.AddGameObject(instance);
}

This allows for example, if you have 10 different models of Trees and export the placements of the "Trees" collection in Blender, to place all of your trees with the correct model at once. All of the models needs to be in the same subfolder though.

Methods

Method Return type Description
GetPlacements(string path) List<(string meshName, Transform transform)> Reads a placements JSON file at the given virtual content path and returns its entries, or null and logs an error if the file isn't found
