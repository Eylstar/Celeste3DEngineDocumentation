Using the Blender Plugin

Guide
This Add-On is still in active development, expect its panels and options to change between Engine versions.

Placing hundreds of trees or rocks by typing out positions in code isn't optimal. This addon lets you build that layout visually in Blender instead, then export it straight into something the Engine can read.
It's found in the Blender Plugin folder of the Engine's zip, alongside the mod itself.

It does two separate jobs, exporting the placements of many object instances as a single JSON file, and exporting individual models as GLB optimized files. Both are covered below.

Installing

In Blender, go to Edit > Preferences > Add-ons > Install..., and select the .py file from the Blender Plugin folder. Once installed, tick the checkbox next to its name to enable it. Blender 5.0.0 or higher is required.

A new C3DEngine tab appears in the 3D Viewport's sidebar, press N if the sidebar isn't already open.

The two panels of the Blender Add-On (more may be coming)

Exporting Models

This panels allows you to very quickly export a Model into an optimized GLB file, ready to use, without having to do the steps manually each time.

These GLB files are meant to be used with the Celeste Engine only. To keep them the smallest possible, the export automatically strips out anything the Engine never reads, every material channel besides Base Color and Normal, vertex colors, and any custom properties.
Opening one of these exports in another tool or a different engine will very likely be missing data you'd normally expect a GLB to keep.


To use it, Select an object in the Model Export panel, give it an output folder, and press Export Model to save it as a GLB.

File Name field is entierly optionnal. If left empty, the pugin will automatically export the model name, without the blender instance number at the end. Tree_Base_Tall.005 will automaticall exported as Tree_Base_Tall.glb. This can be very useful if you use both the model export and the placement export at the same time, so the JSON can automatically find your model to load.

Origin Placement, checked by default, resets the object's position, rotation and scale to the origin before exporting, so the model comes out clean and can be freely repositioned later through code or a placements file. Uncheck it if you specifically want the model exported with its current transform baked in.

Compress Textures (JPEG), also checked by default, exports the model's textures as JPEG instead of PNG, which is a lot smaller for photographic textures and saves a lot of Model export size. Uncheck this if your texture needs transparency (such as foliage).

Exporting Placements

Once your models are placed and duplicated across your Blender scene the way you want, select the Collection containing them in the Placements Export panel, give it an output folder and a name (placements.json by default if non is set), and press
Export Placements.
Just like the Model Export panel, the .001 suffix is automatically removed into the export.

This walks every mesh in that Collection, including anything nested in sub-Collections, and writes out a single JSON file with each object's name, position, rotation and scale. See the JSONPlacements page for the exact format and how to load it back into the Engine.

Not every placement exported needs to be for Rendering Models. Exporting multiple Cubes placed across the Blender scene can be used to automatically create and place BoxColliders at the right place and scale. The Blender objects needs to have a "Mesh" to be included in the export though.

With the two panels, a typical workflow cann look like : modeling or importing 3D assets, exporting each one once with Model Export, then duplicating and arranging as many instances of them as you like directly in Blender before exporting the whole layout in one go with Placements Export.
