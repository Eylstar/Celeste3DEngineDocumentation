Your First Project

Guide

This little tutorial walks through everything you need to know to get a 3D scene showing up in Celeste. From loading the EngineEntity, building a scene, adding your own logic and UI to it.

1. Mod Setup and Folders

The first important step, and common to every project you'll make, is to make and respect a folder/naming hierarchy. What I present to you is a convention, it's based on the already existing Everest one, and it's better if we all follow the same. Of course, it's up to you to respect it or not, depending on your needs.

The actual standard is to have a folder "3DEngine" in the Graphics one, right next to the very common "Atlases" folder. Then from here, you can create the 5 main folders the Engine will search in : Models, Textures, Exports, Audio and Fonts (or only the ones you'll need if you know in advance).

Like any other Everest asset, then in these 5 folders you create one subfolder with your map name, and one with your name, to prevent any possible confilct. And then you can place your data in this last folder

Basic Folder Hierarchy
You can create as many subfolders you want : You can simply put all your models in the Models/Map/Name/.. folder, but you can also create subfolders to organize them better. For functions that needs a model name, instead of typing "playerModel" you'll need to type "characters/playerModel" if you place your player's model in a "characters" subfolder.



Once the folders are set up, you need to reference the Engine in you mod IDE to be able to use its functions. Start by downloading the zip of the Celeste3DEngine, place it like any other mod in your mods folder, and unzip it. (You can delete the .zip version if you don't want them both).

Once done and once you have set up your own code mod (see the main Celeste discord/Everest wiki if needed) you'll need to add the reference to the Celeste3DEngine.dll found in the unzipped mod (bin folder).

Finally, don't forget to add the engine as a dependency into your own mod everest.yaml, using the latest version.

2. Loading and hooking the Engine

Once you did the folder setup and linked your code mod to the engine in the IDE, you can create and open your own map with Lonn.

The Engine provides the Celeste Entity "EngineEntity". Place one in your room and fill in the five path attributes of the Entity (modelsPath, texturesPath, exportsPath, fontsPath and audioPath), pointing at the folders you setuped before. This tells the Engine where to find your assets.
Strings should look something like this : "Graphics/3DEngine/Models/MyMap/MyName". Don't put a / at the end of your string.

Note that you don't need to fill every field if you don't use them, you can leave an empty string. Paths can also be changed at runtime, see EnginePaths page.

You can also say if you want the engine to be persistent or not (more information at the end of this tutorial). If you want to use the engine in multiple rooms, you should set it as persistent, otherwise it will be destroyed when leaving the room and rebuilt when coming back.

Once placed in a room, the Engine doesn't build anything on its own, it just loads itself and waits. You need to create your own CustomEntity with a lua file to place it in Lonn to use the Engine.

Your own code hooks into the engine with EngineEntity.OnEngineLoad, usually subscribed from the constructor of your custom Entity placed in the same room. It's your code that's gonna feed the engine your models, textures and custom code for it to run.

Here is the base code example for the custom entity :

A minimal entry point 
[CustomEntity("mymod/sceneBuilder")]
public class MySceneBuilder : Entity
{
    public MySceneBuilder(EntityData data, Vector2 offset) : base(data.Position + offset)
    {
        EngineEntity.OnEngineLoad += OnEngineLoad;
    }

    void OnEngineLoad(EngineEntity engine, Scene scene)
    {
        Logger.Info("SceneBuilder", "EngineEntity loaded !");
        // All the scene creation can happen here
    }

    //Don't forget to unsubscribe from events
    public override void Removed(Scene s)
    {
        base.Removed(s);
        EngineEntity.OnEngineLoad -= OnEngineLoad;
    }

    public override void SceneEnd(Scene s)
    {
        base.SceneEnd(s);
        EngineEntity.OnEngineLoad -= OnEngineLoad;
    }
}

If everything was done correctly you should see the "SceneBuilder", "EngineEntity loaded !" log in the console. This means the engine is running, and your code mod linked to it.

3. Scene Creation and Rendering

A Scene3D is what actually holds all of your 3D content. Creating one doesn't render anything by itself, you need at least one camera set as the main one, and something for it to look at. Creating a Scene3D creates a default main camera inside it, but you can at any time create another one and change it, useful if you want to directly place it and rotate it without having to Get his reference in the loaded scene. (see Scene3D and Camera3D pages)

For a first scene, DefaultGameObjects are the fastest way to get something on screen without needing any models yet. (See GameObject page)
Here's a simple prototype of a basic Scene3D with the default SkyBox, one floor and one cube :

A camera, a floor and a cube 
void OnEngineLoad(EngineEntity engine, Scene scene)
{
    //Create the Scene Object
    Scene3D myScene = new Scene3D();

    //A camera looking at the origin
    Camera3D cam = new Camera3D();
    cam.transform.SetPosition(new Vector3(0f, 6f, -9f));
    cam.transform.LookAt(Vector3.Zero);
    myScene.AddGameObject(cam);
    myScene.SetMainCamera(cam);

    //Creates a floor and a rotated cube with Default static properties
    GameObject floor = GameObject.DefaultPlane;
    floor.transform.SetScale(new Vector3(10f, 1f, 10f));
    myScene.AddGameObject(floor);

    GameObject cube = GameObject.DefaultCube;
    cube.transform.SetPosition(new Vector3(0f, 0.5f, 0f));
    cube.transform.Rotate(new Vector3(0f, 30f, 0f));
    myScene.AddGameObject(cube);

    myScene.GetRenderer().SetHDMode(true);

    //Load the Scene in the EngineEntity
    EngineEntity.LoadScene(myScene);
}

If everything until now was done correctly, you should get a Scene like this, with already working SkyBox, Lighting and shadows. See Scene3D or LightingSettingsfor changing the skybox and how the lighting and the shadows behaves once you want more than the default settings.

Above code's render with the Engine
Note that I added myScene.GetRenderer().SetHDMode(true) in the code for better visual clarity during the tutorial. A lot of people may prefer the internal Celeste pixel art resolution, by default the HD mode is off and you can change the mode at ease, even during runtime.

4. Loading custom Models

Now that the scene is loaded and functional, it's time to load our own models to customize it. I've used this free Strawberry model here : link. Download the .glb version and put it inside your Models folder.

Now to load the model, we need to create a custom MeshRenderer with the data. Since it's a GLB model, only the model name (without extension) needs to be passed to the MeshRenderer. If you want to use a OBJ mode, you'd need a spearate texture in your texture folder and give them both to the MeshRenderer. More info on its documentation page.

Loading the strawberry model and put it in the scene 
void OnEngineLoad(EngineEntity engine, Scene scene)
{
    //Create the Scene Object
    myScene = new Scene3D();

    ...

    //Create a berry empty GameObject, placed and rescaled
    GameObject berry = new GameObject(new Vector3(3f, 0.5f, -1f), Vector3.Zero, Vector3.One * 0.5f, "Berry");

    //Create its MeshRenderer component with the model name and add it to the object
    MeshRenderer berryRend = new MeshRenderer("strawberry");
    berry.AddComponent(berryRend);
    myScene.AddGameObject(berry);

    //Load the Scene in the EngineEntity
    EngineEntity.LoadScene(myScene);
}
The strawberry object added and placed in the scene

5. Adding Custom code and Behaviour

One of the main features of this engine and its component pattern, is that you can very easily add your own custom code to control objects and/or the rendering of the scene. Every custom code needs to be inside a class that inherits Behaviour and is added to a GameObject like any component. Then by overriding the appropriate functions, you can code what you want.

Here, we want to make our berry simply move with the arrow keys. We start by creating a custom controller class, put code in its Update function and apply this to the berry.

Moving the berry with the arrow keys 
//We create the Behaviour that will control our berry
public class BerryMovement : Behaviour
{
    //public property to control its speed
    public float speed = 2f;

    //overriding Update, called once per frame
    public override void Update(float deltaTime)
    {
        base.Update(deltaTime);
        Vector3 movement = Vector3.Zero;

        //Registering the inputs pressed
        if (MInput.Keyboard.Check(Keys.Up)) movement.Z += 1f;
        if (MInput.Keyboard.Check(Keys.Down)) movement.Z -= 1f;
        if (MInput.Keyboard.Check(Keys.Left)) movement.X += 1f;
        if (MInput.Keyboard.Check(Keys.Right)) movement.X -= 1f;

        //If we have any movement, we normalize it and move the berry using its transform
        if (movement != Vector3.Zero)
        {
            movement.Normalize();
            movement *= (speed * deltaTime);
            gameObject.transform.MoveBy(movement);
        }
    }
}

//Then we simply add it to our berry
void OnEngineLoad(EngineEntity engine, Scene scene)
{
    ...

    BerryMovement berryMovement = new BerryMovement();
    berryMovement.speed = 3f;
    berry.AddComponent(berryMovement);
}

Now, if you input your arrow keys, you should see your berry moving freely in your scene !

Update will always comes with a deltaTime value. Always use it if you make your objects move / behave in the scene. deltaTime is basically the time beetween this frame and the previous frame, and multiplying the movement by it ensures that even at lower framerates, the physics remains accurate across all players.

6. Simple Physics Collisions and Detections

Now our berry can move freely in the scene, but it passes through the cube, and anything. We need to use the couple Collider3D and CollisionDetector to enable physics calculations for our objects. (More information on their respective pages).

For this example, we will add a wall in the back of the scene, against which the berry will collide and slide, and make the cube a trigger collider that changes color and make the berry disappear if they touch each other.

Here's how you can first create the wall, add both BoxCollider and be able to see them into your scene :

Creating the wall and adding a trigger to the cube 
void OnEngineLoad(EngineEntity engine, Scene scene)
{
    ...
    //Wall creation
    GameObject wall = GameObject.DefaultCube;
    Transform wt = new Transform(new Vector3(1.5f, 1f, 2.5f), new Vector3(0f, 25f, 0f), new Vector3(6f, 2f, 0.5f));
    wall.SetTransform(wt);
    myScene.AddGameObject(wall);

    //Wall collider and Box trigger collider creation
    BoxCollider3D wallCollider = new BoxCollider3D(Vector3.One, Vector3.Zero, Vector3.Zero);
    wall.AddComponent(wallCollider);

    BoxCollider3D cubeTriggerCollider = new BoxCollider3D(Vector3.One, Vector3.Zero, Vector3.Zero, true);
    cube.AddComponent(cubeTriggerCollider);

    //Enables drawing the colliders into the scene
    myScene.debugShowColliders = true;
}
The wall and Box colliders correctly drawn into the scene
The default cube returned by GameObject.DefaultCube is a standard cube of size (1,1,1). Since the base Collider size is also (1,1,1) and the collider size scales with the object's Transform, we can simply let the size of the collider with Vector3.One be scaled with the Object directly. This may not always be true with your custom models tho. Colliders are also moved and rotated along the object's Transform

But only doing this don't allow collisions for the berry itself, and we can't just add a SphereCollider3D, colliders don't interacts with other colliders. (see CollisionSystem). We need to add one (or multiple) CollisionDetector to our objects. Here, since the berry has a volume and a detector is a single point in space, we add 4 CollisionDetector (up, front, left and right) to the berry to register its collisions.

We also add the trigger action invoke to the Cube, so when the berry interacts with it, the custom code is called :

Creating the detectors and the OnTriggerEnter event 
void OnEngineLoad(EngineEntity engine, Scene scene)
{
    ...
    //Creating the 4 detectors and adding them to the berry
    CollisionDetector berryFront = new CollisionDetector(3f, new Vector3(0f, 0f, 0.5f));
    CollisionDetector berryBack = new CollisionDetector(3f, new Vector3(0f, 0f, -0.5f));
    CollisionDetector berryLeft = new CollisionDetector(3f, new Vector3(0.5f, 0f, 0f));
    CollisionDetector berryRight = new CollisionDetector(3f, new Vector3(-0.5f, 0f, 0f));
    berry.AddComponent(berryFront);
    berry.AddComponent(berryBack);
    berry.AddComponent(berryLeft);
    berry.AddComponent(berryRight);

    //Setting the trigger enter event that makes the cube turn red and the berry disappear
    cubeTriggerCollider.onTriggerEnter += (detector) =>
    {
        if (detector.gameObject.name == "Berry")
        {
            //Access to the Material inside the MeshRenderer to update it
            cubeTriggerCollider.gameObject.GetComponent<MeshRenderer>().GetMaterial().Color = Color.Red.ToVector3();
            detector.gameObject.Destroy();
        }
    };

    myScene.debugShowColliders = false;
}

Now with this code added, you should be able to move the berry, make it collide and slide against the wall, and if it touches the cube, it disappears and the cube turns red.

7. Adding UI

Now the next step will be to add a basic UI to the scene. UICanvas is the container for that, and it comes in two modes, Overlay, which draws to the screen like a regular HUD, and WorldSpace, which places content as an actual panel inside the 3D scene. (More information on both on the UICanvas page).

Each canvas can hold text with a TextRenderers or images with UISprites.

We'll build one of each canvas type here, starting with an Overlay HUD with a title with a timer and a heart icon. (Find online a simple PNG heart icon and put it in your Textures folder)

Building the Overlay HUD 
//Called from where you want, OnEngineLoad for example
void CreateUI()
{
    //Screen space HUD, Overlay is the default canvasType (myScene variable was made global, easier to use)
    UICanvas hud = new UICanvas();
    myScene.AddGameObject(hud);

    //Title with timer, centered at the top of the screen
    TextRenderer title = new TextRenderer();
    title.textData.content = "Example scene | Playing since ";
    title.textData.position = new Vector2(960f, 60f);
    title.textData.fontSize = 70;
    title.textData.shadow = true;
    title.textData.shadowOffset = 2.5f;
    hud.AddTextRenderer(title);

    //A little rotated heart icon on the right side of the screen
    UISprite heart = new UISprite("heart", new Vector2(1820,90), Vector2.One * 0.2f);
    heart.SetRotation(45f);
    hud.AddUISprite(heart);

    //Add the behaviour that counts time (see just below) to the HUD with the title renderer as a reference
    Timer timerIncrement = new Timer();
    timerIncrement.text = title;
    hud.AddComponent(timerIncrement);
}

//Simple behaviour class that increments a timer
public class Timer : Behaviour
{
    public TextRenderer text;
    float elapsed = 0f;

    public override void Update(float deltaTime)
    {
        base.Update(deltaTime);
        elapsed += deltaTime;;
        text.textData.content = $"Example scene | Playing since  {(int)(elapsed / 60f)}:{(int)(elapsed % 60f)}";
    }
}
Overlay content is always positioned in a fixed 1920 by 1080 reference space, no matter your actual window resolution is. So 960:540 will always be in the center of the Canvas. See UICanvas page.
Fonts can be changed up by placing them in your Fonts folder. Detailled informations in the TextRenderer or EnginePaths pages.

Now for the WorldSpace canvas. Instead of screen coordinates, this one lives in the 3D scene itself, using to its own Transform. So we can position that Transform just above the berry and keep it there as the berry moves.

A nameplate that follows the berry 
void CreateUI()
{
    ...

    //Creating the WorldSpace Canvas and the nameplate
    UICanvas berryNameplate = new UICanvas { canvasType = CanvasType.WorldSpace };
    berryNameplate.transform.SetPosition(berry.transform.Position + new Vector3(0f, 1f, 0f));
    berryNameplate.transform.SetRotation(new Vector3(0f, 180f, 0f));
    myScene.AddGameObject(berryNameplate);

    //Adds the title to the nameplate canvas
    TextRenderer berryName = new TextRenderer();
    berryName.textData.content = "Berry";
    berryName.textData.fontSize = 80;
    berryName.textData.mainColor = Color.Red;
    berryNameplate.AddTextRenderer(berryName);

    //Keeps the canvas above the berry every frame (see behaviour just below). berry was also made global.
    FollowTarget follow = new FollowTarget();
    follow.target = berry;
    follow.offset = new Vector3(0f, 1f, 0f);
    berryNameplate.AddComponent(follow);
}

//Keeps this GameObject's Transform follow a target, plus an offset
public class FollowTarget : Behaviour
{
    public GameObject target;
    public Vector3 offset;

    public override void Update(float deltaTime)
    {
        base.Update(deltaTime);

        //While the berry is not destroyed, move the nameplate over it. If it's destroyed, destroy the Canvas too
        if (target != null && !target.IsDestroyed)
            transform.SetPosition(target.transform.Position + offset);

        else
            gameObject.Destroy();
    }
}
The FollowTarget.Update is a good example on how to access GameObject properties. Before doing so, ALWAYS check if the object is not null and not already destroyed with IsDestroyed, otherwise you may get null reference exceptions. Even if the object is not null, it can already have been destroyed sooner this frame and some properties may become null in this case.
A Title, timer, heart and a "Berry" floating above the berry, following it as it moves

Move the berry around now, the nameplate should stick right above it the whole time, while the HUD stays put on screen regardless of where the camera or the berry go. The "Berry" nameplate can even be hidden by the wall if the berry goes behind it.
