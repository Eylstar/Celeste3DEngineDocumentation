Savestates Crashes

Guide
SpeedrunTool is one of the most widely used mods in the entire Celeste modding scene, a huge number of your players will have it installed. If you skip this page, you may expect some of them to hit a crash when using states.

SpeedrunTool lets players save and reload the exact state of a room instantly, mid run. To do that, it deep clones every Entity in the room, field by field, so it can restore them later exactly as they were.

Without going into technical detail, if any UICanvas in that scene has a TextRenderer on it, that TextRenderer relies on FontStashSharp, an external library used to read and render custom fonts. It wasn't built with Celeste mods or being cloned like this in mind, and trying to deep clone it or clearing his references this way is what actually causes the problem.

When this happens, it doesn't throw a normal exception you can read in the log, it hard crashes the game silently. If you've ever seen a crash like this, this may be the reason.

How to prevent

SpeedrunTool exposes an official ModInterop, a way for other mods to talk to it without needing its assembly to compile or run. So you don't have to have the mod installed to tell it to completely ignore a specific Entity, in this case, our loading mod.

The Engine already does exactly this internally for the EngineEntity itself. This page is about protecting your own loading Entity, MySceneBuilder in our tutorial, the one that actually holds the Scene to the Engine.

First declare the import. This only needs to exist once, anywhere in your mod

Declaring the SpeedrunTool import 
using MonoMod.ModInterop;

[ModImportName("SpeedrunTool.SaveLoad")]
internal static class SpeedrunToolImports
{
    public static Action<Entity, bool> IgnoreSaveState;
}

From your own EverestModule, tell your mod to use the ModInterop

Filling the import in your EverestModule 
public class MyModModule : EverestModule
{
    ...
    public override void Load()
    {
        ...
        typeof(SpeedrunToolImports).ModInterop();
    }
}

And finally, use and invoke it in every of your Entity's constructors

Making MySceneBuilder invisible to SpeedrunTool 
public MySceneBuilder(EntityData data, Vector2 offset) : base(data.Position + offset)
{
    //Tells SpeedrunTool to leave this Entity alone entirely, if it's installed
    SpeedrunToolImports.IgnoreSaveState?.Invoke(this, true);

    EngineEntity.OnEngineLoad += OnEngineLoad;
}

The second parameter, true, prevents your Entity's Added and Removed from firing during the brief remove and re-add SpeedrunTool does internally. Since MySceneBuilder unsubscribes from OnEngineLoad in Removed, you don't want that triggered by a save state load that has nothing to do with actually leaving the room, so be sure to pass true as the second parameter.

The ? in ?.Invoke matters, IgnoreSaveState stays null if the player doesn't have SpeedrunTool installed, ModInterop() only fills it in when the target mod is actually present. This keeps SpeedrunTools a soft, optional interaction, you never need to add it as a dependency in your everest.yaml.
Even if your second constructor used for the EngineCallbacks never ends adding the Entity to the Celeste Scene, it still is a good habit of preventing SpeedrunTools to detect the entity in every constructor, just in case.
