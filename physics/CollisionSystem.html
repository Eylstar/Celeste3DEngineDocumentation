CollisionSystem

Class Internal

The CollisionSystem is what actually detects and resolves collisions for a Scene, but unlike Renderer3D you never get a reference to it, it's fully internal. This page exists to explain how it works, so Collider3D, CollisionDetector and RayCast make sense once you start using them.

Colliders vs Detectors

The system splits collision into two separate roles, and every object involved in physics needs to be one, the other, or both.

A Collider3D is the obstacle, a wall, the ground, a pillar. It defines a shape in space and is never moved or pushed by the collision system. The Collider still move if his GameObject does.

A CollisionDetector is the thing that experiences collisions, the player, an enemy, anything that should be stopped by walls or notified when it touches something. It's the CollisionDetector that gets pushed out and moved, never the Collider3D.

Two Colliders never interact with each other, and two Detectors never interact with each other either. Only Collider3D against CollisionDetector produces a collision / trigger call.

A wall and a player 
//The wall is the obstacle
GameObject wall = new GameObject("Wall");
BoxCollider3D wallCol = new BoxCollider3D(new Vector3(10f, 4f, 1f), Vector3.Zero);
wall.AddComponent(wallCol);

//The player is what gets stopped by it
GameObject player = new GameObject("Player");
CollisionDetector detector = new CollisionDetector(distanceToCheck: 1.5f);
player.AddComponent(detector);
myScene.AddGameObject(player);

//Both sides can react to the same collision with an embeded collision parameter :
detector.onCollision += (col) => Logger.Info("Game", $"{detector.gameObject.name} bumped into {col.gameObject.name}");
//or
wallCol.onCollision += (det) => Logger.Info("Game", $"{det.gameObject.name} bumped into {wallCol.gameObject.name}");

Trigger Enter, Stay and Exit

A Collider3D can be set as a Trigger one with isTrigger set to true, and it doesn't push anything, it only fires events. onTriggerEnter fires the first frame a Detector is found inside it, onTriggerStay fires every frame after that while it remains inside, and onTriggerExit fires the frame it's no longer detected inside.

If a trigger Collider or an entire GameObject gets destroyed while a CollisionDetector is still inside it, a matching onTriggerExit is fired first, so Enter and Exit always come in pairs, even if something disappears mid overlap.

Broadphase with a Spatial Hash Grid

The scene is divided into a grid of fixed size cells, 10 units per cell. Every Collider3D is inserted into every cell its bounds touch. Every frame, each CollisionDetector only queries the cells within its own distanceToCheck radius, instead of testing against every Collider in the scene.

The distanceToCheck isn't a broadphase shortcut, it's the actual maximum distance allowed between the Detector's position and a Collider's surface before that Collider gets tested, checked against each Collider's, not just which cell it's in. Set it too small and a Collider that's genuinely a bit further away than the Detector's own size won't be detected, even one sitting right next to it in the same cell. Set it too large and nothing breaks, it just checks more Colliders than it needs to every frame.

Dirty Flags and Caching

Colliders aren't reinserted into the grid every frame, they stay in their cells until something marks them dirty. Moving, rotating or scaling a GameObject through its Transform does this automatically, so does toggling a Collider3D's enabled or changing its CenterOffset. BoxCollider3D's own size and rotation properties do it too. Only dirty colliders get their grid position and shape cache recalculated each frame.

If you write a custom Collider3D with fields that affect its shape, call MarkColliderDirty() when a change occurs, otherwise the spatial grid and any cached shape data won't necessarily reflect your changes.

Debugging

Setting Scene3D.debugShowColliders to true draws wireframes for Colliders and debug spheres for Detectors, debugShowRayCasts does the same for raycasts. Set debugShowOnlyCollidersInRange at true if you want only the loaded colliders (by a detector) to show. Useful to test the detection range of a detector.
