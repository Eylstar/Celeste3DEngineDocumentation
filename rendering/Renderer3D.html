Renderer3D

Class

Renderer3D is the class responsible for drawing everything in a Scene3D, world models, shadows, lighting, and HUD elements. Every Scene3D creates and owns exactly one Renderer3D automatically, you never create one yourself but you access it with Scene3D.GetRenderer().

Almost everything this class does happens automatically every frame as part of the Scene's normal update cycle, you don't call its rendering steps directly. Its public surface is intentionally small, mostly a couple of settings to control how and whether the scene gets rendered.

Basic Renderer3D usage 
//Getting the renderer from the scene
Renderer3D renderer = myScene.GetRenderer();

//Switching to HD mode, rendering the 3D scene at full resolution instead of Celeste's native buffer
renderer.SetHDMode(true);

//Temporarily disabling all 3D rendering, GameObjects keep updating, they just stop being drawn
renderer.enabled = false;

Rendering Pipeline


Every frame, before anything is drawn to the screen, Renderer3D runs through a sequence of steps to prepare its render targets.

1. Directional light shadow map - if the Scene's LightingSettings has DirectionalLightCastsShadows enabled, the directional shadowMap is rendered. Only GameObjects whose MeshRenderer.castsShadows is true are included.

2. Spot light shadow maps - every ConeLight with shadows enabled gets its own shadow map, up to LightingSettings.maxShadowedLights at a time. Lights beyond that limit are simply skipped for shadows, they still light the scene normally. For each shadow casting spot light, models are culled by distance before being rendered into its shadow map, based on the light's range and each model's bounding sphere. For performance reasons, PointLight can't cast shadows.

3. World models - World and Foreground layer models are rendered into two separate render targets. Any model with MeshRenderer.isFrustumCulled enabled is tested against the camera's frustum using its bounding sphere, and skipped entirely if fully outside of it.

4. Lighting - every enabled Light is applied additively on top of every lit, visible model whose bounding sphere is within the light's range, models further than a light's range plus their own bounds are skipped for that light.

5. UI and HUD - world space UI canvases are rendered into the scene, then HUD models are drawn on top with the depth buffer cleared beforehand, so they always appear above the rest of the scene regardless of distance.

Frustum culling and shadow casting both rely on each Model's bounding sphere, computed from its mesh data in local space and transformed to world space using the GameObject's Transform.

HD Mode

Renderer3D can render the scene in two different ways, controlled by SetHDMode(). With HD mode off, the scene renders at Celeste's native pixel art resolution, matching the rest of the game's gameplay rendering. With HD mode on, the scene renders using the full viewport instead, at whatever resolution the game window currently is.

This choice affects how the 3D scene interacts with the rest of Celeste's rendering. The content of the scene itself still works the same way regardless of this setting. (see MeshRenderer Layer Properties Details documentation part for more information) but it ends up modifying the final post processed rendering of your scene (different hooking placement).

With HD mode off, the 3D scene is drawn into the same buffer Celeste uses for the rest of the room. Any of that room's own rendering settings (darkness, bloom, custom color grade) gets applied to that buffer, over your "flattened" 3D content, the same way they'd affect the room's regular 2D content.

With HD mode on, the scene draws entirely separately, so none of that touches it. If your 3D scene's colors look different in HD than in non HD, this is why.

This also means that you can use the Celeste post processing options to affect your pixel art 3D rendering deliberately. Not doable with HD rendering tho.

Properties

Property Type Description
enabled bool Whether the Renderer3D renders the scene at all, default true, setting this to false skips the entire rendering pipeline for this Scene, GameObject Update logic keeps running as normal
IsHDMode bool Whether the Renderer is currently rendering in HD mode, set with SetHDMode

Methods

Method Return type Description
SetHDMode(bool hdMode) void Sets whether the Renderer should render in HD mode or not
